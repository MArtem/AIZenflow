# Completion Report Contract

## Purpose
Every meaningful completion report must make evidence, scope, and remaining risk explicit.

Use this before saying: done, fixed, verified, safe, clean, production-ready, complete, or ready.

## Required Report Shape
- Scope completed:
- Files changed:
- Durable docs updated:
- Rules applied:
- Checks run:
- Checks not run and why:
- Build/tests status:
- Remaining risks:
- What was intentionally not done:
- Local exceptions created or used:
- Context health: `контекст обновлять не нужно` / `желательно обновить контекст` / `нужен новый чат`
- Model result: which model(s) worked and what each did

## Stop Rule
Do not claim production readiness when relevant gates were skipped. State the remaining risk instead.

Do not hide pre-existing failures. Classify them as out-of-scope, pre-existing, or blocking.
