## Change contract — targeted feed-card upsert lookup

- **Behavior:** preserve the existing upsert rule: update only a record whose card ID and owner match; otherwise attempt insertion. Card encoding, persisted fields and ordering remain unchanged.
- **Authority:** `FeedCardRepository.saveCard` owns record lookup/upsert. The shared `SwiftDataDatabaseManager` still owns main-context save and rollback.
- **Producer/consumer agreement:** `FeedCardStore.updatePersistedCard` must persist before changing its in-memory `persistedCards` and `cards`; `NewsFeedViewModel` continues to refresh channel state after the store call.
- **State/time ordering:** keep the synchronous write contract and update memory only after a successful `saveCard`; do not introduce optimistic UI state or a new actor/task lifetime in this patch.
- **Resource envelope:** query by immutable card ID, bounded to one result because `FeedCardRecord.id` has a unique constraint. Check owner equality after fetch to preserve tenant isolation. No schema, migration, cache or payload-size behavior changes.
- **Failure semantics:** propagate write/fetch errors through the existing database rollback path; a nonmatching owner must not mutate another owner's record. Preserve the existing attempted-insert behavior for a nonmatching owner/unique-ID collision.
- **Affected consumers/claims:** shared repository source is compiled by `TchopApp` and `TchopAppOcean`; the existing repository round-trip test will cover an updated card among an unrelated stored card. No other consumers or public performance claims change.
- **Verification status:** patch and test update are applied; Debug build/install/launch succeeded; F20 exercised Like and showed no hang event, but was not a matched pre/post workload. XCTest was not run. A full final diff review and the single agreed `git diff --check` remain to be recorded. The F19/F21 `SIGTRAP` occurs in AX-heavy automation and remains unresolved as a harness-versus-app termination risk.

## Code findings and static candidates

1. **Feed state construction scales with every card.** `NewsFeedViewModel.screenState` maps all visible cards into view states, and each state may query translation availability (`NewsFeedViewModel.swift:316-329,399-425,443-489`). This runs before `LazyVStack` limits row rendering and conflicts with the model's “cheap to construct” invariant. On supported AI OS paths, availability also enumerates supported languages per eligible card. **P2 candidate; high confidence for the static O(N) work, runtime cost unmeasured.** Capture SwiftUI/Time Profiler at several list sizes and during likes/search.
2. **Search and refresh filtering execute synchronously on the main actor per query edit.** `searchQuery.didSet` calls `refreshVisibleContent`; filtering normalizes each card's fields, builds scores, and sorts matches (`NewsFeedViewModel.swift:268-272,707-721,743-780`). **P2 candidate; high confidence for the synchronous path, user-visible impact unmeasured.** Measure paced/rapid typing and channel changes with Time Profiler/hangs.
3. **Upsert lookup cost on a Like/comments/display-mode write.** F18 showed CoreData fetch/write stacks in the 1.61 s main-thread Hang. `saveCard` now fetches at most one `FeedCardRecord` by its unique ID and then checks owner; synchronous main-context save remains (`AppContentRepository.swift:46-65`; `AppSwiftDataDatabase.swift:4-15,43-75`; `AppShellViewModel.swift:32-118`). **The unbounded full-table lookup is fixed in this working tree and Debug build succeeds. Runtime improvement is not proven: F20 reported no hang but is not a matched capture; persistence stack samples remain.** Next compare identical synthetic feed/query/action states across multiple repetitions and card counts, then decide whether synchronous save itself needs a separate change.
4. **Media preview memory/main-thread work needs measurement.** PDF preview reads the full file into `Data` before thumbnailing; the shared image cache limits count to 160 but has no byte-cost limit; encoded preview data is decoded into `CGImage` on the `@MainActor` loader (`NewsFeedView.swift:1191-1208,1210-1252,1321-1329`). File import copy has no size check visible in the inspected caller/storage path; producer-side accepted-size policy remains unknown. **Unrated candidate until a safe input envelope and trace establish impact.** Capture large-but-bounded synthetic image/PDF cases, Allocations/Leaks and main-thread stacks; distinguish peak, retained and cumulative allocations.
5. **Existing signposts exposed identifiers and local media paths as public.** `FeedCardAppear` logged card ID and `FeedMediaPreviewLoad` logged `fileURLString` as `%{public}s` (`News/NewsFeedView.swift:26-46`). **Confirmed code-level privacy defect; no claim that a user artifact was exposed.** The format strings now mark card ID and file URL private while keeping the low-cardinality media kind public. Static source review and `git diff --check` passed; no build/test/runtime capture was run for this change.

The runtime-performance candidates are not a “no issues” or runtime verdict. No memory leak, battery drain, frame hitch or CPU regression is confirmed without a valid process-bound capture.
