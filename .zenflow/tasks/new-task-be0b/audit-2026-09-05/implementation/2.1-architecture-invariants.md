## Contract

- Behavior: every stateful surface has an explicit owner and render-ready contract, while
  architecture structures are selected by current boundary pressure and project profile.
- Authority: reusable docs define app-neutral invariants; app ADRs remain the authority for an
  adopted style and are not rewritten by this block.
- Producer/consumer agreement: architecture router identifies the existing style before applying
  its gates; UI components receive narrow state/callbacks unless a concrete lifecycle/resource
  boundary justifies a state owner.
- State/time ordering: lifecycle, cancellation, ordering, persistence, availability, and failure
  semantics are named where they affect correctness; render code remains cheap and side-effect free.
- Failure semantics: absence of a ViewModel, Renderer, Coordinator, repository protocol, reducer,
  package, or module is not itself a defect when invariants and ownership are satisfied.

## Desk examples

| Consumer shape | Accepted architecture decision |
| --- | --- |
| Small native SwiftUI screen with local visual state | Keep native state plus narrow child input/callbacks; add no ViewModel, Renderer, or package for symmetry. |
| Existing MVVM app with moderate async screen state | Preserve MVVM, explicit intent methods, one state owner, and render-ready state; do not migrate architecture merely to match a newer template. |
| Complex multi-target app with real navigation/module boundaries | Use Coordinator/module/package boundaries only where targets, lifecycle, team ownership, or dependency direction require them; app composition owns product policy. |

The reusable package standard continues to require current implementation pressure before adding
modules. UI workflow now follows the active model-routing rule and no longer hard-codes Sol for all
visual work. AI Fieldbook ADR-010 and other app decisions remain app-local.
