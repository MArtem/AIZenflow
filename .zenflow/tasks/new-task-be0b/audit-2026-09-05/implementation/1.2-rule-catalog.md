## Contract

- Behavior: active reusable norms have stable IDs and a compact metadata record without rewriting
  their normative text or tagging the whole historical library.
- Authority: the source document named by each catalog entry remains the single normative authority;
  `QUALITY_RULE_CATALOG.md` is an index, not a second rule source.
- Producer/consumer agreement: checklist and production-readiness prompt refer to Rule IDs; task and
  app exceptions must name the ID and version they bypass.
- State/time ordering: draft/proposed exceptions cannot authorize a bypass; expiry, scope drift,
  toolchain/data-flow change, or a new relevant finding makes an exception stale.
- Failure semantics: missing metadata, duplicate IDs, unreachable catalog routing, or malformed
  catalog structure blocks publication of this catalog; unsupported app-local exceptions stay local.

## Catalog contents

The canonical catalog contains 12 active reusable norms:

`QC.AUTHORITY.HIERARCHY`, `QC.VERDICT.READINESS`, `QC.EXCEPTION.CONTRACT`,
`QC.CHANGE.CONTRACT`, `QC.MODEL.ROUTING`, `QC.BOOTSTRAP.GLOBAL`, `QC.DOC.BOUNDARY`,
`QC.EVIDENCE.FRESHNESS`, `QC.STATIC.FAIL_CLOSED`, `QC.CI.MANUAL_ADVISORY`,
`QC.TEST.PERMISSIONS`, and `QC.SWIFT.CONCURRENCY_FLOOR`.

Each entry records ID/version, owner, scope, MUST/SHOULD strength, trigger, enforcement,
limitations, exception policy, evidence, one authority path/anchor, source date, and revisit
trigger. The strict universal concurrency floor remains the default; an exception can only be
scoped and approved through `QC.EXCEPTION.CONTRACT` and does not silently authorize unsafe
annotations or weaken another project.
