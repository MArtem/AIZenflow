## Implemented changes

- Added `swift_lint_tool` with regular non-symlink executable checks, exact `version` output,
  executable-size bound, and SHA-256 digest.
- Added tracked UTF-8 YAML config validation/digest. `disabled_rules`, `whitelist_rules`,
  `only_rules`, and `excluded` are rejected until an explicit suppression/path policy exists.
- Added clean-HEAD Swift source selection, explicit `SCRIPT_INPUT_FILE_COUNT`/`SCRIPT_INPUT_FILE_*`
  environment, `lint --strict --no-cache --reporter json --use-script-input-files`, bounded timeout/
  output, no-autocorrect semantics, and strict JSON finding normalization.
- Added lexical detection of inline `swiftlint:disable`/`enable` directives while masking string text,
  so examples in literals do not become suppression findings. Finding paths must stay within the
  authenticated source root and selected source set.
- Added `QC.LINT.SWIFTLINT` to the deterministic result schema, upgraded its catalog entry from
  staged to implemented, added inert positive/negative fixture projects, and documented the
  Apple `swift-format`/SwiftFormat/SwiftLint distinction.
- Preserved source revision in blocked adapter receipts after checkout identity is observed.

## Acceptance mapping

- Tool missing, non-regular, non-executable, wrong version, version-command failure, or digest
  overflow is `BLOCKED`.
- YAML path/traversal/non-UTF-8/empty/suppression config is `BLOCKED`.
- Clean source list is explicit and bounded; zero tracked Swift sources is `BLOCKED`.
- SwiftLint is asked only to lint and report JSON; no autocorrect or mutable latest download exists.
- Return `0` with non-empty diagnostics is `BLOCKED`; return `1` with structured diagnostics is
  `FAIL`; infrastructure exits, malformed JSON, path escape, and output overflow are `BLOCKED`.
- Inline suppression is `FAIL` with a source line; literal examples remain outside the suppression
  claim. `wired` and `pilotEnabled` remain false until later phases.
