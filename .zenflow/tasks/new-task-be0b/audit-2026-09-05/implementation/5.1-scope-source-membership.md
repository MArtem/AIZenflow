## Contract

| Dimension | Decision |
| --- | --- |
| Behavior | Keep profile `sourcePaths` as explicit scan scopes and emit an independent `sourceMembership` receipt only after an authenticated, stable Xcode compiler log proves a non-empty in-repository input set. |
| Authority | Profile owns scheme/target/configuration/destination declarations; the authenticated compiler log owns observed compiled inputs; Git-tracked files alone never imply shipped membership. |
| Producer/consumer | `XcodeBuildLogMembershipExtractor` → `XcodeBuildEvidenceVerifier` → `XcodeBuildEvidenceCoordinator` → `QualityEvidence`/build-result schema. The coordinator emits `QC.BUILD.MEMBERSHIP` together with structured source membership. |
| State/time | Membership is derived from the same stable build-log reads and result-bundle identity used by the existing build boundary. The command identity binds target names, declared scopes, compiled paths, compiler-section count, and external-input count. |
| Input/resource envelope | Existing log, section, command, repository-input and result bounds remain active; external source-looking inputs are deduplicated and capped. Receipt arrays and strings have matching runtime/schema limits. |
| Failure semantics | Empty, unavailable, malformed, oversized, unresolved, outside-scope, traversal, or symlink-escaping membership produces evidence-free `BLOCKED`; it cannot become normal `PASS`. |
| Affected claims | `QC.BUILD.MEMBERSHIP` is a narrow compiled-input claim. Generated ownership remains `QC.GENERATED.OWNERSHIP`; extension membership is observed rather than inferred; external package inputs are counted outside the first-party list. |

## Implemented changes

- Added `SourceMembershipEvidence` and explicit claim identifiers to the evidence contract.
- Kept `sourcePaths` and `compiledSourcePaths` separate in the receipt, with scheme, target list,
  configuration, destination, compiler-section count, and bounded external input count.
- Counted external source-looking compiler inputs without retaining their absolute paths in evidence.
- Bound membership facts into the command SHA and added a second `QC.BUILD.MEMBERSHIP` gate.
- Required source membership and both build gates in the build-evidence PASS schema branch while
  keeping static evidence backward-compatible with an omitted optional field.
- Added app-neutral acceptance cases covering generated, extension, package, Tests, empty,
  unresolved, symlink, traversal, malformed, oversized, and undeclared-selection states.

## Acceptance mapping for the future permitted 7.1 phase

- A compiler input under `Tests` is surfaced as an in-scope observed input or blocks on a missing
  declared scope; it is never silently hidden.
- A tracked but uncompiled vault/source file is not called shipped by this receipt.
- Generated inputs are allowed only as observed compiler inputs; generated ownership remains a
  separate gate.
- Extension inputs are included only when present in compiler evidence.
- External SwiftPM/package source-looking inputs are counted but excluded from first-party paths.
- Empty, unresolved response/file lists, path escape, symlink escape, malformed/oversized logs,
  and undeclared target/configuration selection cannot produce a normal PASS.

## Residual risk and rollback

The receipt still proves compiler-input membership, not complete product bundle/runtime membership,
resource copying, archive contents, or App Store behavior. Those claims require the later build,
release, and pilot phases. If this contract proves too strict for a real project, pin the previous
engine revision and keep the new membership gate `BLOCKED`/advisory; do not disable existing checks
or reinterpret tracked source as shipped.
