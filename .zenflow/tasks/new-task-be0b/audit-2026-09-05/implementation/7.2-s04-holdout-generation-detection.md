## Isolation

The generator and blind detector received the neutral S04 contract only. Neither context received
the evaluator answer key, truth labels, intended defect location, or bug hints. Detector findings
were recorded before the evaluator disclosed the key. This is a holdout desk/static receipt, not
runtime or durable-store evidence.

## Generator result

Fresh generator context produced `ORBIT`: a staged durable transaction with commit-only
publication, rollback on stage/commit failure, explicit `recoveryRequired` when rollback fails,
and reuse of the same logical key and operation ID for retry. Initial generation quality: **PASS
conditional on its explicit DurableStore assumptions**. No runtime/build/test claim was made.

## Blind detector result before key disclosure

| Neutral variant | Detector verdict | Finding boundary |
| --- | --- | --- |
| `VARIANT-ORBIT` | PASS | New value remains private until commit; old committed snapshot survives failure; rollback/recovery is explicit; retry identity is bounded. |
| `VARIANT-NOVA` | FAIL | Destructive `delete → write` ordering can lose the old value; no transaction, rollback, recovery state, or idempotency marker protects retry. |

The detector marked runtime durability assumptions as uncertainty for ORBIT, while correctly
classifying NOVA as a contract failure from the operation order alone. It did not claim runtime
proof.

## Evaluator scoring after disclosure

The evaluator-only key confirms ORBIT as the acceptable failure-safe replacement boundary and NOVA
as the deliberate data-loss defect. The blind detector therefore produced a correct holdout
detection for the selected open/defect pair. Generation and detection results remain separate;
there is no aggregate quality score.
