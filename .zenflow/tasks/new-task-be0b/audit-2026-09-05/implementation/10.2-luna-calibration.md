## Process comparison

Two process variants were compared using the existing 10.1 route measurement; no new experiment was
commissioned.

| Variant | Use | Evidence | Decision |
| --- | --- | --- | --- |
| A — targeted specialist packet | Small edits, concurrency/data/release/privacy changes, exception work, QC slices, consumer static checks | Current routes preserve authority/permission coverage; concurrency route 1,606 words versus broad route 7,810 words; router and docs checks PASS | Default process |
| B — broad universal reread | Cross-cutting semantic audit, route-source change, or unresolved authority conflict | Necessary when several specialist routes interact; cost and billed-token telemetry remain unknown | Reserve for 11.1 or an explicit cross-cutting change |

The 79% difference is a route-only words comparison, not a billed-token or quality guarantee. No
evidence supports weakening the high-risk review barrier. A smaller packet is acceptable only when
the selected route still covers authority, permissions, state/time ordering, failure semantics,
resource/input envelopes, and evidence identity.

## Operational instructions for future Luna blocks

1. Before editing, write the compact change contract: behavior, authority, producer/consumer
   agreement, state/time ordering, input/resource envelope, failure semantics, affected claims, and
   permitted evidence.
2. Read Level 0, current task state, and the specialist route once. Re-read a source only when its
   identity or contents changed. Do not reread the archive as a substitute for route selection.
3. Keep patches bounded to one coherent block. If more than three source files or a new permission
   boundary is required, stop at the boundary and report the estimate before expanding scope.
4. Run only the permitted static check for the block. Runtime/build/test/CI evidence belongs to the
   owner of that evidence and must be recorded as missing when unavailable.
5. Review the complete final diff against the contract, search affected call sites and mirrored
   claims, and inspect false-success and irreversible-state paths. P0–P2 findings block commit.
6. For high-risk or cross-cutting work, retain a fresh-context semantic review. It is a second
   barrier and never a replacement for direct evidence.
7. Record unknown usage, elapsed time, and denied actions explicitly. Never convert missing data
   into a cost or quality claim.

## Decision

**PASS_WITH_LIMITATION for Luna xhigh process calibration.** Existing observations support a
targeted specialist process as the minimum sufficient default and a broad route only for
cross-cutting semantic audits. The calibration does not prove a relative model price, statistical
quality, runtime readiness, or stable QC promotion. 8.2 remains partial and continues to block
ordinary stable promotion.
