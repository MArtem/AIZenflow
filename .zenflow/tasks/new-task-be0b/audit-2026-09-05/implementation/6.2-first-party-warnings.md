## Contract

The QualityControl build boundary consumes only the supervisor-owned, stable structured
`xcresult` documents. `build-results` warnings and analyzer warnings are normalized into bounded
facts. A diagnostic is assigned to the current revision only when its target is selected and its
repository source is present in authenticated compiler membership. External/dependency inputs and
non-selected targets are excluded; likely generated paths are excluded from the first-party claim.
An otherwise selected-target warning that cannot be attributed is `BLOCKED`.

Build failure, malformed/partial/truncated structured data, unsafe diagnostic paths, empty compiler
membership, unstable result reads, and output/resource limits remain non-PASS through the existing
supervisor. No text-log tail is parsed as a clean-build proof. Exact source revision, engine/profile
identity, toolchain, scheme/configuration/destination, and result artifact digests remain bound by
the existing evidence command and receipts.

This first implementation deliberately does not infer or create a warning baseline. Every
authenticated first-party warning is therefore treated as new. Baseline persistence, review,
expiry, and rollback are a later explicit contract; no baseline is deleted or silently accepted.

## Changes

- `XcodeBuildEvidenceVerification.swift` now emits bounded diagnostic observations with selected
  source-relative or external classification and a conservative concurrency marker set.
- `XcodeBuildEvidenceCoordinator.swift` classifies selected-target/compiler-membership facts,
  excludes dependency/external/generated/non-selected diagnostics, and returns distinct
  `QC.BUILD.FIRST_PARTY_WARNINGS` and `QC.CONCURRENCY.DIAGNOSTICS` terminal results.
- A clean build evidence receipt now contains four PASS gates: `QC.BUILD`,
  `QC.BUILD.MEMBERSHIP`, `QC.BUILD.FIRST_PARTY_WARNINGS`, and
  `QC.CONCURRENCY.DIAGNOSTICS`. Warning-bearing builds return `FAIL` without evidence; an
  unattributed selected-target diagnostic returns `BLOCKED`.
- The build-evidence JSON schema, stable catalog maturity, README, policy README, and schema README
  were updated together. The two new checks are implemented and build-mode wired, but remain
  `verified=false` and `pilotEnabled=false` until the permitted canary/pilot phase.

## Review and residual risk

The final diff was reviewed against the change contract. The main residual is the intentionally
conservative empty-baseline policy: existing first-party warnings fail until a separately reviewed
baseline contract exists. The concurrency detector is a bounded diagnostic-message classifier; its
canary must cover current Swift/Xcode wording before pilot promotion.
