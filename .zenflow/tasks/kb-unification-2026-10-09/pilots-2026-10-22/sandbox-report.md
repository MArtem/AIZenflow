## Вывод

Максимально локализовать проектные файлы, логи, результаты, временные каталоги и compiler caches возможно. Полностью изолированный запуск Xcode/CoreSimulator только выбором этих каталогов не подтверждён. Сейчас Simulator/UI/runtime-проверки18.2/27 имеют статус BLOCKED_BY_USER_SANDBOX, а не PASS. Работу над KB и разрешённые статические проверки можно продолжать. Native-проверки возможны после отдельного анализа их собственных эффектов; уже полученный результат модели Battleship12/12 сохраняется с его узкой областью.

Важно различать:

1. **Проектная граница:** какие исходники читаем/меняем и где размещаем наши outputs. Это управляемо.
2. **Чтение установленного toolchain/SDK:** компилятор, linker и SDK находятся вне .zenflow. Действующее правило разрешает необходимое чтение этих файлов уже авторизованной командой. Это не разрешение читать личные каталоги или писать наружу.
3. **Полная файловая изоляция процесса и его служб:** каталог проекта сам её не создаёт. Перенаправление stdout не ограничивает дочерние процессы, системные службы или произвольные build scripts. Такую изоляцию здесь не аттестовали.

Если понимать запрет буквально как отсутствие вообще любого внешнего чтения, невозможно даже использовать установленный macOS/Xcode toolchain. Текущая рабочая трактовка сохраняет существующее узкое исключение на чтение системных executables/SDK; никаких новых внешних writes это не разрешает. Переопределение HOME, симлинки на Library, отключение системной защиты или обход sandbox не применялись и не предлагаются.

## Что проверено без запуска Simulator

- Прочитано правило CURRENT_USER_OVERRIDES: Absolute boundary и исключение на установленный toolchain/SDK.
- В локальной man-странице xcodebuild подтверждены `-derivedDataPath` и `-resultBundlePath`. Это пути отдельных outputs, не обещание полного отсутствия других writes.
- Прочитана установленная Xcode-обёртка `usr/bin/simctl`: она проверяет version CoreSimulator и при отсутствующей/старой версии условно вызывает `xcodebuild -runFirstLaunch`, затем исполняет системный backend. Условная ветка не запускалась; её наличие не доказывает, что она сработала в прежних вызовах.
- В строках установленного backend подтверждено `usage: ... [--set <path>] [--profiles <path>] ...`. Backend не запускался. Строки бинарника подтверждают наличие интерфейса, но не полную семантику и не isolation guarantee.
- Ранее обычный `simctl list` сообщил об обращении к `/Users/Artem/Library/Logs/CoreSimulator/CoreSimulator.com.apple.CoreSimulator.simctl.log` и device set `/Users/Artem/Library/Developer/CoreSimulator/Devices`; последовал отказ/потеря связи. Это наблюдённая попытка внешнего доступа, не доказательство успешной записи. Один предыдущий успешный список runtimes не означает успешного запуска приложения.
- Проверены owned пути P01-native: tmp, Swift module-cache, Clang cache, compile/run logs и receipt существуют, не являются симлинками на верхнем уровне и разрешаются внутри .zenflow. Переиспользованы compile/run exit0 и12/12 PASS. Syscall tracing не выполнялся; отсутствие всех внешних побочных writes этим не доказано.
- В текущей проверке не вызывались simctl, Simulator.app, xcodebuild, first-launch, install/mount, networking или новые compiler/test runs. Личные каталоги Library не читались. Читались только указанные файлы установленного toolchain и наши артефакты.

## Матрица возможностей

| Действие | Максимум внутри .zenflow | Что остаётся вне или неизвестным | Решение сейчас |
|---|---|---|---|
| Чтение/правка исходников и KB, JSON/Markdown, diff/структурные проверки | Все project inputs/outputs под разрешённым корнем; проверять resolved paths и не переходить по внешним ссылкам/симлинкам | Интерпретатор/системные библиотеки читаются вне корня; произвольный checker сначала требует чтения его кода | Разрешённый основной режим; проверять каждый исполняемый скрипт по scope |
| Git локально | Рабочее дерево и repo metadata могут быть в .zenflow | Git может читать глобальную конфигурацию, исполнять hooks/filters; linked worktrees делят refs. Обычный status не является сертификатом полной hermetic isolation | Только уже разрешённые scoped операции после анализа; никаких новых публикаций приложений |
| Отчёты, stdout/stderr, xcresult, screenshots как файлы | Явные output paths полностью под .zenflow | Перенаправление одного лога не перенаправляет все логи производителя/службы | Сохранять здесь; источник данных требует своей авторизации |
| Native Swift/domain regression | Бинарник, TMPDIR, module caches, наши compile/run logs можно задать внутри; P01 это продемонстрировал | Чтение SDK/библиотек внешнее; побочные эффекты runtime/OS не проверены; XCTest/SwiftPM могут иметь другой профиль | Разрешать только понятный bounded native check с явными путями, не обещать нулевых OS writes |
| Xcode build без запуска приложения | DerivedData, result bundle, многие build/intermediate outputs направляются в корень | Xcode service/preferences/cache, scripts/plugins/macros, package resolution, signing и first-launch могут обращаться наружу. Даже build-only не считается автоматически безопасным | Полное соблюдение внешних writes не доказано; не запускать спорную сборку как эксперимент ради выяснения |
| SwiftPM/dependency operations | Некоторые scratch/cache/checkout paths настраиваются | Точные параметры текущей версии здесь не проверялись; plugins/binary artifacts/network/global metadata требуют отдельного анализа | Не выполнять resolve/download/install; не считать cache override достаточным |
| Custom Simulator device set | Интерфейс `simctl --set <path>` найден; device data можно попытаться разместить под корнем | Это не перенос CoreSimulatorService, host logs, runtime mounting/state и всей инфраструктуры; функционирование в этом режиме не проверено | Не запускать: недостаточно доказательств соблюдения запрета |
| Обычный Simulator / UI/XCTest на iOS18.2/27 | Test result bundles и часть app/device data можно локализовать | Наблюдалось обращение к пользовательской Library; системные службы и runtime живут вне корня | BLOCKED_BY_USER_SANDBOX; не повторять попытки и не запрашивать снова отказанные пути |
| Simulator runtimes / Xcode first-launch / signing / archive / Instruments | Можно выбрать отдельные output files | Есть системное состояние, services, provisioning/keychain/host configuration; output path не изолирует эти операции | Не выполнять в текущей области |
| Сеть/GitHub/CI/browser/cloud tools | Локальный отчёт может быть в .zenflow | Выполнение/передача данных вне файловой песочницы; расположение отчёта ничего не говорит о data boundary | Не использовать как замену заблокированному Simulator без отдельной текущей области |

«Разрешённый режим» здесь означает соответствие текущей scope/policy при проверенном инструменте, а не доказанную системную изоляцию от всех OS writes. Внешняя директория, которую система читает как toolchain, не становится доступной для произвольной работы агента.

## Что меняется в пилотах

- Пилот P01: native logic12/12 PASS; UI18.2/27 BLOCKED_BY_USER_SANDBOX. Нельзя объявлять весь пилот прошедшим.
- Для остальных проектов доступны scoped code/contract/target-membership review, анализ существующих тестов и зависимости, статические проверки разрешённых файлов. Runtime claims остаются отдельными и непроверенными.
- Не обходить отказ переходом к глобальному HOME, повторными elevated simctl вызовами, контейнером/VM/installers или удалённым CI. Новую инфраструктуру не строить ради этой проверки.
- Сначала документировать вопрос проверки и доступное evidence; если нужна runtime-проверка, которую текущая граница запрещает, оставить BLOCKED вместо создания видимости PASS.
- Новый порядок/статический этап следующего пилота можно выбрать отдельно; текущий отчёт не запускает P02 и не переписывает всю программу тестов.

## Предел заключения

Это ограниченная проверка интерфейсов, обёртки и прошлых результатов, не security audit macOS и не доказательство абсолютно всех файловых эффектов. Полная изоляция CoreSimulator не подтверждена и не объявляется невозможной во всех иных средах; в текущем разрешённом окружении оснований запускать его нет. Неизвестные возможности log-root overrides не выдаются за поддерживаемые и работающие настройки.

Контекст обновлять не нужно. Локальные исключения не созданы. Исходники приложений не менялись. Для этого отчёта build/tests не требовались. Каноническая task-копия публикуется по standing documentation authority; AIZenflow app Git и upstream repositories не меняются автоматически.
