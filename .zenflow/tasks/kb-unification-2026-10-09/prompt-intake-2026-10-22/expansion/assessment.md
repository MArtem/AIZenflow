# Расширение пользы промптов

Запрос пользователя: максимально использовать полезные приёмы комплекта. Реализовано в трёх существующих логических владельцах, без импорта отдельной конкурирующей системы.

## Как это применяется

Preflight теперь выбирает процедуру по типу задачи; при неясном выборе iOS процедуры или специалиста обращается к существующему iOS prompt router. Это условная ссылка, не новая обязательная загрузка всего router. Пользователь не обязан помнить номера промптов. Router выбирает процедуру по результату: feature, диагностика, миграция, concurrency, UI, архитектура, security, AI, ревью или incident/release. Для каждой есть минимальный полезный результат и существующий владелец. Профильная глубина включается по механизму риска, а не случайному слову.

Из W1–W9 и T1–T12 адаптированы: минимальный контракт; конкурирующие проверяемые гипотезы; постепенная миграция и ограничения rollback данных; владелец и interleaving concurrency; состояния UI; реальные архитектурные альтернативы и revisit trigger; trust boundaries; соответствие claims доказательствам; разделение containment/fix и release decision. Делегирование, санитизация/экспорт, runtime и benchmark не активированы.

Completion prompt расширен: trigger→execution/state→нарушенный контракт→эффект; поиск существующей защиты и попытка опровержения finding; различение риска и подтверждённого бага; границы доказательств и неподдержанные claims. Это направляет самопроверку, не создаёт независимого ревью.

## Охват источника

prompt-application-map.json содержит все 135 ID, заголовки, предметную семью, существующий входной owner и disposition. Семейный entry owner — навигационный вход, не утверждение, что один документ покрывает каждую техническую деталь. METHOD_ADAPTED означает перенос методического приёма; REFERENCE_VIA_EXISTING_ROUTE — использование уже принятого предметного маршрута, а не новую сертификацию содержания. P024 отмечен частичным конфликтом. Исходный source-review.json сохраняет точные прежние пределы чтения. Workflows/templates перечитаны целиком в этом блоке; лаборатория/код/DOCX не проверялись и не выполнялись.

## Статическое рассмотрение

Без model runs и тестовых файлов вручную рассмотрены: короткая feature→существенные вопросы; баг без reproducer→разрешённый static анализ без ложного root-cause claim; миграция→данные отдельно от code rollback; stale search→ownership/interleaving; UI→актуальные состояния/локали; спорная архитектура→минимальный вариант/триггер пересмотра; security profile→не менять runtime/network; AI→существующий router, не обязательные layers; review→опровергнуть ложный finding; release→не запускать rollout; механическая правка→не требовать artifacts; P024→отклонить unsafe escape; excluded device check→OMITTED_BY_USER.

## Ограничения

Это инструкции и статическая согласованность, не enforcement и не измеренный выигрыш. Новых тестов, моделей, агентов, tools, runtime, платформ или требований продукта нет. Нет новой Level 0 нагрузки; расширен только выбранный task context. Авторизация AIZenflow commit/push не выводится из запроса. Каноническая публикация выполняется в рамках standing authority. Локальных исключений нет.
