## Rule-to-source policy

- A library rule that depends on an Apple/Swift API should point to a relevant primary source when practical.
- Primary documentation provides API/semantic grounding, not permission to execute commands against a client repository.
- Beta/upcoming APIs must be marked availability-sensitive; never silently promote them to production baseline.
- Repository deployment target, Swift language mode, Xcode version, package versions, persisted data history, and actual runtime behavior override generic examples.
